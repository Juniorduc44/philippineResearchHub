# Projects workspace

Last updated: 2026-09-20

## What happens here
This is where a catalog idea becomes a build. One folder per slug. The directory entry stays thin; the project holds Lean experiments, E-Myth systems, Profit First accounts, and Philippines operations.

## What the work is
Turn a filed idea into something that can be tested at one site without the owner living inside the machine. Structure comes from three local books:

- Lean Startup (Hungarian HVG 2013 scan) — one question, one MVP, measure real behavior, pivot or persevere
- E-Myth Revisited — work on the business; franchise prototype; operations manuals; positions before people
- Profit First — take profit first; five accounts; 10/25 rhythm; new-business starter percentages

## Process
1. Every idea in `directory/INDEX.md` gets a folder here, even if it is only a shell.
2. Active builds fill `lean/`, `emyth/`, `profit-first/`, `philippines/`.
3. Claims about PH law or money cite `research/library/` or stay `unknown`.
4. Operator notes (the drop-in idea briefs) are sources, not proof.

## What good looks like
- A stranger can run the next experiment from `lean/mvp-experiment.md`.
- Systems are written as if a second unit will clone the first.
- Cash has named accounts before the first peso of revenue.

## What to avoid
- Expanding two ideas in one folder.
- Writing novels. One screen per file unless it is a manual.
- Filling Profit First with fake percentages. Use starter CAPs until real revenue exists.

## Files
- `INDEX.md` — all project folders
- `<slug>/CONTEXT.md` — that idea’s build rules
