# 1.3 How to Structure Any Prompt (extract)

A prompt is an instruction set. Five parts; you will not use all five every time.

1. Identity — role. In this hub, `CLAUDE.md` already does this for ongoing work.
2. Task — action + scope + enough detail that a stranger could start.
3. Context — constraints, audience, prior decisions the model would not know. Project-level context lives in workspace `CONTEXT.md`.
4. Constraints — what to avoid.
5. Output format — shape of the answer.

Shortcut: simple → task only. Creative → identity + task + constraints + format. Complex → all five. Ongoing project → identity/context in files; task/constraints/format in the prompt.

Chunking: one prompt, one clear thing. Review between steps. Feed long inputs in sections after the table of contents. Keep tables as tables.

The folder is memory. The prompt is direction.
